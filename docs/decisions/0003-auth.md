# ADR 0003 – Authentication & Authorisation

## Status
Accepted

## Context
We need secure authentication, four distinct roles, and tier-based authorisation for downloads and the web reader.

## Decision
- Use **Encore Auth** as the only authentication system.
- Roles stored on the user record:
  - `user` (default)
  - `uploader`
  - `moderator`
  - `admin`
- Roles are enforced both in Encore middleware/guards and in frontend route loaders.
- Subscription tier is a separate concept from role and is checked on every download / reader request.
- Moderators receive notifications for flags; only admins can change roles, tiers, and payment settings.

## Consequences
- No NextAuth, Auth.js, Clerk, Supabase Auth, or custom JWT implementations.
- Frontend never trusts its own role claims; it always re-fetches `/auth/me` or relies on the generated client.
- Admin and moderator routes are protected by both frontend guards and backend permission checks.
- `last_seen_at` is updated on authenticated activity to power the “online users” KPI.
